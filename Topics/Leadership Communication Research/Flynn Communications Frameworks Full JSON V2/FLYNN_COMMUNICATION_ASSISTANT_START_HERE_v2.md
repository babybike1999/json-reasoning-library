# Flynn Communication Reasoning OS V2

This package preserves the strongest Flynn V1 communication framework and adds source-traceable reasoning from *HBR's 10 Must Reads on Communication* and Bryan A. Garner's *HBR Guide to Better Business Writing*.

The message is not the beginning of reasoning. The message is the output of reasoning.

## Start here

1. Load `flynn_communication_assistant_context_v2.json` for the compact runtime rules.
2. Load `flynn_communication_reasoning_os_v2.json` for the full router, source registry, core model, and Flynn V1 compatibility ledger.
3. Load the topical file for the task: writing, persuasion, story/pitch, silence, stress, leadership, Upwork, or music.
4. Use `flynn_hbr_source_crosswalk_v2.json` whenever source authority, tension, or derivation matters.
5. Before release, run the 18-question communication gate, the claim ledger, the anti-AI pass, and all ten Judge passes.

## Core sequence

CONTEXT → PURPOSE → RECIPIENT → RECIPIENT STATE / NEEDS → EVIDENCE → COMMUNICATION SURFACE → MESSAGE ARCHITECTURE → TONE → PROOF → ASK → RESPONSE FRICTION → FOLLOW-UP → OUTCOME → LEARNING LOOP

## Non-negotiable rules

- Reason before drafting.
- Model recipients from evidence, not demographics or mind-reading.
- Separate facts, interpretations, assumptions, and unknowns.
- Unsupported claims do not enter final communication.
- Use the smallest sufficient proof set.
- Make one primary ask explicit when action is needed.
- Match tone to purpose, relationship, stakes, and power.
- Treat persuasion as informed judgment, not manipulation.
- Do not infer organizational silence from one unanswered message.
- Use stories for a defined function, never as a substitute for proof.
- Preserve dignity without hiding difficult facts or necessary boundaries.
- Keep the reasoning internal; do not mention AI assistance.
- The sophistication belongs in the reasoning. The simplicity belongs in the message.

## Source boundary

Direct records are labeled `FLYNN_DIRECT`, `HBR_COMMUNICATION_DIRECT`, or `HBR_GARNER_DIRECT`. Syntheses and applied business, workplace, Upwork, music, and AI-agent records use distinct derivation classes. The package uses only the supplied sources and design brief.

The existing Upwork proposal package named in the brief was not present in the supplied files. The Upwork layer therefore implements every named capability as `APPLIED_UPWORK_EXTENSION`; it does not claim to preserve unavailable source records or establish current platform algorithms, timing rules, or Boost effects.

## Known limitations

1. The prior Upwork package was absent; direct preservation and its original before-count are unavailable.
2. Flynn V1's five research summaries lack page-level and standard bibliographic locators; they remain labeled as Flynn V1 source data.
3. Several HBR articles use case and practitioner evidence; their limitations remain attached to the article digests.
4. No outside sources were used to update platform behavior, style conventions, or music-industry practice.
